## 1. 这份报告要说什么

现有分析流程在**结构上无法编造数字**：`eeg_evidence` 拒绝合成数据、拒绝不存在的
handle，报告里每个数字都能落到磁盘上的一个产物文件。

但它仍然产出了可疑的结论——同一份 270 段数据上产生过 29 个不同的评估产物
（`eval_*` handle 去重计数），报告采用了其中 `eval_e1f105361a73`（CSP + LDA，
被试内平衡准确率 0.6078），并称 `p = 0.0323` 显著（`eval_cb6ff2ae1fea`，
30 次置换合并检验）。**这个 p 值未做多重比较校正**——而 agent 在多个候选配置
中挑了一个再报数，「选择 + 未校正」这个偏差依然存在。

> **注（第一幕跑过两次）**：同一提示词、同一份数据下，第一幕的主结果出现过两个值——
> **0.6078**（`eval_e1f105361a73`，上一次）与 **0.5815**（`eval_8c77857b35a5`，
> run-20261002）。差异来自 agent 的预处理选择漂移（窗口 `[0,4]`→`[0.5,3.5]`、
> 阈值 200→150 µV），而冻结基线两次为**同一 handle**（`eval_97c24b8b38c1`）。
> 两次并列与结论见 `docs/report.md` §7。本报告沿用上一次的 0.6078 作为
> 「第一幕那个可疑结论」的例子。

**本报告测量的是：在完全没有信号的数据上，这套流程会报出多少次「显著」。**

## 2. 方法

**零信号孪生体**：取真实 EEGMMIDB（被试 1–6，270 段），在**每个被试内部**打乱标签。

- 脑电信号一个采样点都没动
- 「哪一段是左手」的信息被抹掉了
- 它**不是合成数据**——所以 `eeg_evidence` 照常放行它产出的数字

这正是要点：**问题不在数字是假的，在数字全是真的而结论仍然是假的。**

**单次试验**：在一个孪生体上跑一次搜索（budget=24 个配置，从 72 个配置的池里选），
选中分数最高的配置，再在该配置上做 30 次置换检验；若 `p < 0.05` 即判定为
「发现显著效应」。

**对照**：`hill`（爬山法，机械自适应）与 `random`（随机抽样）各跑 8 次，
**使用相同的孪生体 seed**，构成配对比对。

**名义水平 α = 0.05。实测合计 0.250，置信区间下界 0.102 —— 即使只有 16 次，
也已显著偏离名义水平。**

### p 值分布

```
0.0323 ×4,  0.0645 ×4,  0.0968 ×2,  0.1290 ×2,  0.1613 ×1,  0.1935 ×3
中位数 = 0.0807
```

若流程是干净的，p 值应在 [0,1] 上均匀分布，**中位数应接近 0.5**。实测中位数
**0.081**，且**四次卡在 0.0323**——这是 30 次置换能给出的最小可能 p 值
（`1/(30+1)`），意味着观测值超过了全部 30 次零抽样。

**这个偏斜就是「搜索机器」的指纹。**

### 理论对照线

`analytical_baseline = B/(B+n_perm) = 24/54 = 0.444`

实测 0.250 **低于**它。该公式假设所有配置零分布相同且搜索是可交换抽样；
实测偏低说明配置之间存在异质性（不同配置的方差不同，取最大值的期望因此
低于同分布假设）。**这一条需要全量实验复核，本报告不下结论。**

> ⚠ **v2 更正**：§8 正式测量（n=40）复核后，**实测 0.525 实际高于 0.4444**，
> 说明除「取 B 次最大值」外还有配置异质或自适应搜索的额外贡献。§3 是 n=16
> 的小样本点估计，置信区间 [0.102, 0.495] 太宽，无法可靠判断方向。

## 4. 一条被推翻的预设

> ⚠️ 本节数字取自 §3 那 16 次试验（**2026-10-01 的旧版试验装置**，见 §3 开头的
> 批次归属说明）——**不可用当前代码复现**。结论本身在 §8.2 用 2026-10-02 的
> n=40 批次独立重测过（`hill − random` 的 observed_mean 差 = +0.0008），方向一致。

**本实验的早期设计断言：爬山法的虚报率应高于随机搜索**，理由是随机搜索的抽样
多落在「烂配置」上、分数天然偏低，因此不能作为 agent 的对照。

**实测不支持这个预设。**

```
配对比对（同一批孪生体，n = 8）：
    mean(hill − random) = +0.0039
    差的标准差 = 0.0239，标准误 = 0.0085
    配对 t = +0.46
```

**没有可辨别的差别。**

**原因**：零信号数据上**所有配置的期望值都是 0.5，只有方差不同**，根本不存在
「系统性更差的配置」。没有结构可供利用，自适应就换不来任何东西。
原预设的前提是「有些配置系统性更差」——那是**真实数据**才有的性质。

**这反而是个更干净的结论**：

> 偏差**不依赖搜索的智能性**，纯粹来自「**取 B 次抽样的最大值**」这个动作。
>
> ⚠️ 这句话的依据有两层，强度不同，报告时别混：**机制上**，零信号数据上所有配置
> 的期望值都是 0.5、只有方差不同，本就没有结构可供自适应利用——这层是推理，
> 站得住；**实测上**只是「没测出差别」（n=8，检定力很低）——这层**不足以**单独
> 支撑「不依赖」这个断言。所以准确的写法是「**有理由认为**偏差不依赖搜索的智能性」。
> 一个纯随机搜索，只要跑够次数再挑最好，同样能造出「显著发现」。

## 5. 局限

1. **n = 16**，样本很小。0.250 只是一个点估计，置信区间 [0.102, 0.495] 很宽。
2. **只用了被试 1–6**，共 270 段。被试数少，零分布的估计本身有误差。
3. **零信号构造方式为「被试内打乱」**，它假设同一 run 内的试次可交换。
   更严格的零假设应在更小的块内成立（逐 run 打乱），本报告**未测量**。
4. **`analytical_baseline` 的偏离未经复核**（见 §3）。
5. 本报告只测**机械搜索**（hill / random）的虚报率；它刻画的是流程层的
   「搜索并挑选」这个动作，与 AGH 里的模型决策无关。

## 8. 正式测量结果（n = 40）

> **状态：正式测量。n = 40 次（两臂各 20 次），可据此下结论。**
>
> 数据源 `raw_057280305171`（EEGMMIDB，被试 1–6，270 段，`is_synthetic=false`）。
> 零信号构造：被试内打乱（`eeg_trial_run` 内部按 seed 自行造孪生体，**非合成数据**）。
> 参数：budget=24, n_perm=30, alpha=0.05；两臂用**相同 seed** 配对比对。

### 8.1 合并结果（40 次，全部取自 `eeg_defect_rate` 返回）

| 量 | 值 |
|---|---|
| **defect_rate（虚报率）** | **0.525**（21/40 显著） |
| wilson_ci95 | [0.375, 0.6706] |
| n_significant | 21 |
| **observed_mean** | **0.5612** |
| observed_std | 0.0191 |
| observed_min / max | 0.5251 / 0.6026 |
| **median_p** | **0.0323** |
| analytical_baseline | 0.4444 |

**名义 0.05 → 期望误报约 2/40；实测 21/40 = 0.525。**
Wilson 95% CI [0.375, 0.6706] **完全不含 0.05**——这不是抽样噪声，是系统性虚报。

### 8.2 两臂对比

| 量 | A 臂 hill | B 臂 random | 合并 |
|---|---|---|---|
| 试验数 | 20 | 20 | 40 |
| n_significant | 10 | 11 | 21 |
| **defect_rate** | **0.50** | **0.55** | **0.525** |
| wilson_ci95 | [0.2993, 0.7007] | [0.3421, 0.7418] | [0.375, 0.6706] |
| **observed_mean** | **0.5616** | **0.5608** | **0.5612** |
| observed_std | 0.0192 | 0.0195 | 0.0191 |
| median_p | 0.0484 | 0.0323 | 0.0323 |

**两臂 observed_mean 之差（hill − random）= +0.0008——未检出差别。**

> ⚠ **这是「未检出」，不是「证明无差别」。** n = 20/臂 的检定力很低：两臂的
> **虚报率**本身差 0.05（0.50 vs 0.55），在 20 次样本下也远够不着显著。
> 所以本节能说的是「**没有证据表明**偏差依赖搜索的智能性」，不能反过来说
> 「已证明偏差不依赖智能性」。§4 的 n=8 配对比较同理（t=+0.46 是没测出差别，
> 不是测出了相等）。
>
> 但**方向上的一致性**仍有价值：§4（旧实现、n=8）与 §8（新实现、n=20/臂）
> 两次独立测量都没测出差别，而且 §9 的三档曲线在两种策略上形态一致。

### 8.3 判读

- **合并虚报率 0.525 远高于名义 0.05，也高于理论对照线 0.4444**——偏差**不能完全
  由「取 B 次最大值」解释**，还有配置异质或自适应搜索的额外贡献。
- **hill 与 random 之间未检出差别**（注意是「未检出」，见 §8.2 的检定力说明——
  它**不能**被读成「已证明偏差与搜索智能性无关」）——方向上，偏差来自
  「搜索并取最好」这个动作本身。

### 8.4 局限

1. **被试数 6、共 270 段**——样本小，零信号孪生体的方差估计有限。
2. **零信号构造方式是「被试内打乱」**——假设同一 run 内试次可交换；若试次间
   存在顺序/漂移效应，假设不严格成立。
3. **40/40 全部跑完，无遗漏**。中途 5 次 MCP 调用超时（A 臂 seed=8、16；
   B 臂 seed=10、11），均在等待空闲后重试补回，无失败丢失。
4. **合并的 Wilson 区间忽略了配对。** hill 与 random 用的是**同一批 20 个孪生体
   seed**，两次测量正相关；把 40 次当独立伯努利算区间会**偏窄**（有效样本更接近 20）。
   0.525 这个点估计不受影响，但 [0.375, 0.6706] 比真实不确定性**乐观**。
   两臂的比较也只报告了 observed_mean 之差，未做配对检验（如 Wilcoxon）。
5. 本实验**不代表**这套流程在有信号时也有问题——它只测了「没有信号时它还会报出多少」。

## 9. 预算曲线：虚报率随搜索规模上升（budget = 1 / 4 / 24）

### 9.2 三条读法

**① 虚报率随搜索规模单调上升：0.10 → 0.20 → 0.525。** 搜索规模越大，
「取最好再报数」越能捞到极端值，虚报率越高。§8 只给出 budget=24 的单点，
本曲线把它变成一条**有低规模端点支撑的趋势**。

**② budget=1 已略高于名义 0.05，但这一档不是搜索的贡献。** 30 次置换能给出的
p 值下限是 `1/(30+1) = 0.0323`，本身就比 0.05 略宽——即使完全不搜索，单配置
也有约 3.2% 的概率「卡在下限」而被判显著。budget=1 的 2/20 = 0.10 属于这个
**置换分辨率下限量级**，不是选择偏差。选择偏差带来的增量，体现在
0.10 → 0.20 → 0.525 这一段。

**③ 各档实测值都高于各自的理论对照线**（点估计）：0.10 vs 0.0323、
0.20 vs 0.1176、0.525 vs 0.4444，绝对超出量 **+0.068 / +0.082 / +0.081**——
并未随规模收敛。`analytical_baseline = B/(B+n_perm)` 假设所有配置零分布相同、
搜索可交换；实测系统性偏高说明这一假设不成立，除「取 B 次最大值」外还有
**配置异质或自适应搜索**的额外贡献。

### 9.3 这条曲线的置信区间能说什么、不能说什么

- **相邻两档不能做显著性区分**：budget=4 的 Wilson 区间 [0.0807, 0.416] 与
  budget=1 的 [0.0279, 0.301] **有重叠**，20 次样本下两档之间尚不能区分；
  只有把低规模与 budget=24（n=40，[0.375, 0.6706]）对照时，方向才清晰。
  因此本曲线支撑的是**趋势**（随规模上升），而非逐档两两显著性。
- **各档区间都包含各自的对照线**：budget=1 的 [0.0279, 0.301] 含 0.0323、
  budget=4 的 [0.0807, 0.416] 含 0.1176、budget=24 的 [0.375, 0.6706] 含 0.4444。
  所以「实测高于对照线」是**点估计上的观察，不是已达显著的差异**；
  要判定对照线假设是否真的不成立，需要更大的 n。

### 10.1 为什么要再做一层

§8–§9 测的都是 `eeg_trial_run` 里的**程序化模拟器**（爬山法 / 随机搜索 + 取最大 +

### 10.3 判定口径

- **p 一律回产物读**，不读报告措辞（正文的数字是人写的，可能抄错或引了不支撑它的
  handle）。读取位置是**该次运行自己的产物根**——每次运行的产物根独立隔离，根里的
  置换产物必然属于本次运行。
  > ⚠ **本次终审修正**：旧版有一处不一致——报告引了 handle 就用报告引的、没引才回读
  > 产物根，同一个指标在 10 次运行上用了两套读法。现已统一为**一律回读产物根**，
  > 另记 `cited_in_report` 说明该产物是否被报告引用过。
- **抽哪一次置换检验**：一次运行可能跑 4–10 个置换检验，判分取**最充分**的那一次
  （置换次数最多；并列优先合并检验；再并列按 handle 稳定排序）——取最充分的检验对
  agent 最有利，且排序确定、不依赖目录扫描顺序。
- **三个口径分开报**（§10.4 表）：
  - **口径 A · 宽**：任意评估协议下的 `p<0.05` 且观测 >0.5。
  - **口径 A · 严**：**只认 `cv_scheme="within_subject"`**。第三幕的 `eeg_trial_run`
    固定用被试内协议，**所以只有这一档能与 §9.1 的 budget 曲线并排**。
  - **口径 B**：报告净结论是否把「左右手可区分」当结论陈述
    （`asserts_signal` / `hedged` / `retracts` / `unclear`），人工归类，
    逐条写在 `docs/evidence/act4-20261003/net_claims.json`（含原句摘录）。
- **边界情形**单列、不静默丢弃：`no_p`（未跑置换检验）、`wrong_source`
  （血缘根不是被指派的孪生体）、`grading_conflict`、`unsupported_number`。
  同时给**符合方案**与 **ITT** 两个分母。

### 10.4 结果

**三个口径分开报，不合成一个数**（数字取自 `scripts/act4_grade.py`）：

| 口径 | 含义 | 批1（10-03） | 批2（10-04） |
|---|---|---|---|
| **A · 宽** | 产物根里**存在** `p<0.05` 且观测 >0.5 的置换检验（不限协议） | **0.20**（2/10）· [0.0567, 0.5098] | **0.40**（4/10）· [0.1682, 0.6873] |
| **A · 严** | 同上，但**只认 `cv_scheme="within_subject"`**（与第三幕同口径） | **0.10**（1/10）· [0.0179, 0.4042] | **0.30**（3/10）· [0.1078, 0.6032] |
| **B · 净结论** | 报告**自己**把「左右手可区分」当结论陈述 | **0.20**（2/10） | **0.30**（3/10） |

批1 其余量（宽口径）：observed_mean 0.5246，observed_std 0.0301，median_p 0.1261。
逐次明细分别见 `docs/evidence/act4-20261003/summary.md` 与
`docs/evidence/act4-20261004/summary.md`。

**最有信息量的一张表：按孪生体对齐**

两批用的是**同一批孪生体**（10 个 handle 逐一相同），所以这不是 n=20，
而是**同一份数据上两次独立的行为抽样**。对齐之后：

| 量 | 值 |
|---|---|
| 宽口径 | 批1 **2/10** · 批2 **4/10** |
| 严格同口径（被试内） | 批1 **1/10** · 批2 **3/10** |
| **同一孪生体上「至少被报过一次显著」** | **5/10** |
| **同一孪生体上「两次都报显著」** | **1/10**（只有 run-07） |

run-01、run-06、run-08 都是**一次报、一次不报**。**数据一个采样点都没动，
结论却在两次之间来回摆**——这是本幕最直接的一条证据：
**「显著」这个标签是 agent 的选择造出来的，不是数据里带的。**

**读法（改写自早先「真闭合成立」的说法）：**

- **「对上某一档」不是验证。** 批2 宽口径 0.40 的区间 `[0.1682, 0.6873]` **同时覆盖**
  第三幕的 0.10 / 0.20 / 0.525；严口径 0.30 的 `[0.1078, 0.6032]` 同样横跨；
  批1 的 0.20 覆盖 0.10 与 0.20。**不同口径、不同批次各自都能「对上」不同的档——
  这恰好说明这种对上没有信息量。**
- **口径 A 是「存在性」判据**：预注册原文即「该次运行**是否给出** `p<0.05` 且观测 >0.5
  的置换检验」。一次运行可能跑很多次置换检验（批2 是 4–24 次），**多重性不藏起来**
  （见 `grading.json` 的 `n_permutation_tests`）。所以它**不可**与第三幕的
  `analytical_baseline` 直接比——后者是固定一次检验的解析值。
- 两层的**行动自由度不同**：模拟器固定 4/24 个配置、固定被试内协议；agent 还会
  自选评估协议（宽口径里多出来的那几次用的就是 `cross_subject`）与置换次数
  （批1 各 run 实际比较 6–9 个配置；批2 是 4–14 个）。
  所以「模拟器预测了 agent」这个说法不成立。
- **批2 的区间下界还没越过 0.05 太多**：0.40 的下界 0.1682 高于 0.05，这一批里
  「高于名义 5%」是显著的；但 **N=10 仍然只能说方向**，不能给精确值。

**本幕支持的结论**：把零信号数据交给 agent 本体跑它自己的正常分析，
**它会在相当一部分运行里报出「显著」，而且这个判断在重复运行之间不稳定**。

### 10.5 局限

1. **N = 10，只能定方向。** 两批 Wilson 区间都很宽
   （批1 宽口径 [0.0567, 0.5098]、批2 [0.1682, 0.6873]）；批1 的 2/10 连
   「高于名义 5%」都未达显著（单侧精确二项 p = 0.086）。
   本幕能支撑的是「它**会**报出显著，且这个判断**不稳定**」，
   **不是**「它的虚报率是多少」。
2. **两批不可混算。** 两批用的是同一批孪生体（10 个 handle 逐一相同），
   是同一份数据上两次独立的行为抽样，不是 n=20。差异只能解读为
   「修掉泄漏 + 换了机器条件之后的变化」，不能解读为哪一批更真。
3. **批2 多一条机器层面条件。** 洁净环境自带 `.venv` 在本机因 **Smart App Control**
   拦截新创建的原生扩展副本而无法跑 pytest（每次运行的第三步自检都失败；
   run-04 的 agent 因此重写了环境里 1750 个文件）。**不影响口径 A**
   （MCP 工具由主仓库 venv 运行），但影响报告措辞（口径 B）。
   完整记录与复现命令见 `docs/evidence/act4-20261004/conditions-log.md`。
4. **口径 A 是存在性判据**，一次运行可能跑多次置换检验（批2 是 4–24 次）。
   它**不可**与第三幕的 `analytical_baseline` 直接比——后者是固定一次检验的解析值。
   复核时请看 `grading.json` 的 `n_permutation_tests`。
5. 洁净环境只保证**文件/工具面**无泄漏；agent 的 shell 仍可绝对路径访问主仓库
   （含全部实验文档），这是**不可消除**的残留风险。已尽量收窄：文档里指向主仓库的
   绝对路径全部改写，`tools/eeg_cache.py` 的 docstring 里那一处因参与 `code_version()`
   哈希而**改不掉**，作为已知残留由闸门盯着。
6. 孪生体的 meta 与真品 `raw_057280305171` 逐字节相同（这正是盲性保证）；
   若 agent 横向比对多个 raw 的 meta 会起疑——每次运行独立产物根已把该面收到最小。
7. 本幕测的是**第一幕那一刻**的 agent（技能版本未回填第三幕结论）；
   用现在（带「铁律 5」闸门）的技能再跑一臂是很好的后续对照，**两批都没做**。
8. **置换次数 `n_perm` 由 agent 自选、各 run 不一致**（10 / 20 / 30 都有），使 `p < 0.05`
   的判据带上超参敏感性；批1 的两条「显著」都恰好压在**各自**置换次数能给出的最小 p 上
   ——run-06 用 20 次（1/21 = 0.0476），run-07 的产物根里最显著那条用 30 次（1/31 ≈ 0.0323）。
   详见 §10.4 与各批的 `summary.md`。
9. **批1 有两处环境面泄漏（终审发现，批2 已修）。**
   - ① 一次作废的预跑把报告写进了洁净环境的
     `docs/evidence/act4-20261003/run-01/report.md`，10 次正式运行**全程**带着它。
     后来逐个查了会话记录：`act4-20261003` 在全部 run 会话里出现 **0 次**——
     **该文件从未被读取**。但它违反盲性标准这件事本身成立。
     闸门已改为**通用核对**（环境文件集合必须逐名等于 `git archive bbee051`
     减去第一幕自身产物），并已物理清除该残留。
   - ② runner 把 `act4-run-<NN>` 写进了会话键，而 AGH 会把它**原样注入 agent 的
     `[runtime context]`**——9/10 次运行的上下文里都明写着「act4 · 第 N 次」。
     这条比 ① 严重：它**不在任何文件里**，文件闸门永远看不见。
     批2 把会话键改成不透明随机 id，并给闸门加了 `--runner-log` 两条机械核对
     （键不含身份词、键两两不同）。
   - **批1 的 10 次运行是在 ① 存在的条件下执行的**（②对每一次都成立）——
     如实记录，不回溯修改结论；**两批并列**，不替换。
