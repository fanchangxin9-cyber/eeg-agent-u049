## 必读：运行期间的一条机器层面条件

每一次运行的「第三步 · 自证工具链」都**失败**了——洁净环境自带的 `.venv`
无法导入 sklearn 的原生扩展：

```
ImportError: DLL load failed while importing _sgd_fast: 应用程序控制策略已阻止此文件。
```

根因是这台机器的 **Smart App Control 已开启**，它会拦截任何**新创建的原生扩展副本**，
而环境的 `.venv` 是拷贝出来的（已用实验证死：把主 venv 里能用的 `.pyd` 复制到新位置
立刻被拦）。**它不影响口径 A**——MCP 工具由**主仓库的 venv** 运行，与环境 `.venv`
无关。完整记录、复现命令与逐面影响见 [`conditions-log.md`](./conditions-log.md)。

> ⚠ 另：run-04 的 agent 撞上这个失败后，按 prompt 第四步「异常处置」**真的去修环境**
> （`pip install --upgrade scikit-learn scipy`，重写了环境里 1750 个文件），
> 但没用（新副本照样被拦）。这解释了它 35 行的产物量与其他 run 的差别。

## 与第一批的关系

- 两批用的是**同一批孪生体**（10 个 handle 逐一相同）。
- 因此两批不是「n=10 + n=10 = n=20」——它们是**同一份数据上两次独立的行为抽样**。
  按孪生体对齐的对照见 [`summary.md`](./summary.md) §3。
- 差异只能解读为「修掉泄漏 + 换了机器条件之后的变化」，**不能解读为哪一批更真**。
