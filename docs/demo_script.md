# 演示视频分镜与口播稿（3–5 分钟）

> ⚠️ **绝对不要在视频里念出任何你没有当场跑出来的数字。**
> 本仓库早期版本的分镜里曾有一句编造的「准确率 68%」，而且是被真人念出来的。
> 指南 §13 把「伪造实验数据、运行记录」列为取消资格情形，念数字比写文档更严重。
> 本版全部改为**按屏幕实际输出口播**。

> ℹ️ **配音可以用 AI 生成。** 指南只要求视频「以实际操作为主」，不禁止 AI 配音。
> 但注意界线：**声音可以是合成的，画面必须是真实录屏。**
> 用 AI 生成假的界面或拼接未真正跑通的流程，属于伪造运行记录。

---

## 总原则

- **全程实操**，不用 PPT 假装。指南明确要求「以实际操作为主」。
- 评委要看的是**闭环**：任务输入 → 执行 → 外部能力调用 → 反馈调整 → 结果验证 → 异常处理。
- 六项要素缺一不可，其中「反馈调整」最容易漏，而它恰是「AGH 与模型执行闭环」占 20% 的得分点。
- 不要加速。Agent 思考时的等待本身就是「在做决策」的证据，可用字幕说明它在看什么。

## 一、录制前的准备

### 1. 初始化 git（同时满足指南的「保留版本记录」要求）

```powershell
cd D:\暂存\source
git init
git add -A
git commit -m "EEG Agent: 参赛作品"
```

这一步还有额外好处：AGH 的 subagent 隔离依赖 git worktree。

### 2. 确认数据已缓存（**必须**，否则视频里要等一小时下载）

```powershell
dir $env:USERPROFILE\mne_data\EEGBCI\MNE-eegbci-data\files\eegmmidb\1.0.0\
```

应看到 S001–S006 共 18 个 `.edf` 文件。

### 3. 确认 MCP 已连接

设置 → MCP，`eeg-agent` 应为 **已启用 / 连接正常**，工具数 **10**。

### 4. 先完整试跑一遍

确认流程顺畅、时间不超 5 分钟。**试跑用的是缓存数据，第二次会快很多。**

### 5. 确认测试全绿

```powershell
.venv\Scripts\python.exe -m pytest tests\ -q
```

## 三、口播稿（可直接粘贴到 TTS）

> **TTS 使用说明**
>
> 1. 稿子里**刻意避开了 EEG / CSP / MCP 这类英文缩写**——中文 TTS 读到夹在中文里的英文，常会念错或念成一串字母。如果要加，请手写成 `E-E-G`、`C-S-P` 这种形式。
> 2. **建议按段落分别生成配音**，再逐段拖到对应画面。整段生成不好对齐，因为工具调用有等待时间。
> 3. 全文约 780 字，正常语速约 3 分 20 秒；留出等待画面动作的停顿，正好 4 分半到 5 分钟。
> 4. 「（读屏幕实际值）」是提示你自己看着屏幕念，**不要把括号念出来**。

### 段 ① 开场（0:00–0:20）

这是我们的参赛作品：一个基于 Agnes Harness 的脑电智能体。

它解决的是一件很实际的事——脑机接口要落地，最大的障碍不是算法，而是每个人都不一样。同一个「想象左手」，不同人的脑电模式差别很大，所以必须逐人调参。这个过程目前全靠人工经验，费时、而且难以复现。

我们让智能体来承担这个判断过程。

### 段 ② 任务输入（0:20–0:45）

现在我们只说一段自然语言：分析六个被试的运动想象数据，先看质量再决定方案，每调一次配置就汇报结果和理由。

注意第一句话——我要求它先规划。

### 段 ③ 规划（0:45–1:10）

它先把计划列成了清单。这是「智能体」和「脚本」的第一个区别：脚本不会自己写计划。

### 段 ④ 诊断（1:10–1:40）

它没有直接开始分析，而是先做体检：幅值正常吗？有没有坏电极？哪个被试样本太少？

（**读屏幕上的诊断结论**）

诊断完之后，才决定处理方案。

### 段 ⑤ 迭代（1:40–2:20）

第一轮成绩是（**读实际值**）——和瞎猜差不多。

于是它换了个思路：现在用的特征是「频段功率」，太粗糙，而且做了全脑平均，把左右的差异抹平了。它改用一种专门为这类信号设计的空间滤波方法。

成绩跳到（**读实际值**）。

**这是整段演示里最关键的地方——这个调整不是脚本里写死的，是它看了结果之后自己做的决定。**

### 段 ⑥ 验证（2:20–3:00）

它把两种评估协议都跑了一遍。被试内是（**读实际值**），跨被试是（**读实际值**）。

而且它主动说明：跨被试接近随机，是这个领域的公认难题，不是实现问题。

还有一点：单次调用装不下三十次打乱重排，它就**分三批各跑十次，再自己合并**——因为检验的精度下限由次数决定，次数不够会把真实的效果误判成不显著。合并之后，结果是（**读实际值**）。

**它没有藏。**

### 段 ⑦ 自证（3:00–3:30）

接下来它做了一件我们没要求的事——主动调用命令行，跑了一遍项目的测试套件。

（**读实际结果，例如「42 个测试全部通过」**）

它在用工具证明自己的工具链是正常的。

这个弹窗是 Agnes Harness 的审批门：命令行操作每次都需要人工确认，不能自动执行。

### 段 ⑧ 异常处理（3:30–4:00）

我们再给它一个失效的结果编号，看它怎么办。

它拿到了错误码、原因，还有一份可用编号的清单，然后自己换了一个继续跑——**没有停下来问我**。

### 段 ⑨ 证据与报告（4:00–4:40）

最后它生成报告。这里有一条硬规则：报告里的每一个数字，都必须来自工具真实跑出来的证据表，找不到出处的写不出来。

这不是靠提醒它「别编数字」，而是**在结构上让它编不出来**。

报告里专门有一节叫「局限」，写了被试太少、个体差异大、统计上还有保留。包括一个失败的结果：跨被试确实做不到，我们如实报告了。

### 段 ⑩ 收尾（4:40–5:00）

我们的作品不是「用 AI 分析脑电」，而是——

**造了一个会自己想办法、并且说真话的实验员。**

谢谢。

## 四、演示输入原文

**在 AGH 里新建会话**（工作目录必须是 `D:\暂存\source`），复制整段：

```
使用 eeg-analysis skill，完成一次完整的 EEG 运动想象解码分析。
这是参赛作品的演示，请把过程做扎实。

【第一步：先规划】
用 todo 工具列出你计划执行的步骤，再开始动手。

【第二步：分析】
分析 EEGMMIDB 被试 1-6 的运动想象数据，判断左右手能否区分。
要求：
- 先做质量诊断，根据诊断结论决定预处理方案，不要套用固定参数
- 每调一次配置就汇报指标，并写清「观察 → 决定 → 理由 → 下一步」
- 两种交叉验证协议 within_subject 和 cross_subject 都跑并分别报告
- 做置换检验证明结果不是流程泄漏造成的。注意 p 值下限是 1/(n+1)，
  次数不足会把真实效应误判为不显著；单次调用装不下时按 skill 里的办法
  分批再合并
- 与冻结基线对比，给出增益并说明来源

【第三步：自查】
分析完成后，用 shell 工具运行项目的测试套件自证工具链正常：
  .venv\Scripts\python.exe -m pytest tests/ -q
并解释三类测试（正常/边界/失败）各自覆盖了什么。

【第四步：异常处置】
过程中如果任何步骤失败，判断它是否可恢复：可恢复就调整后重试，
不可恢复就记录原因并说明用什么替代证据弥补，不要跳过不提。

【第五步：出报告】
用 eeg_evidence 收集所有可引用的数字，然后写中文报告到 docs/report.md，
六个部分：数据概况、方法（含为什么这样选）、结果、验证、与基线对比、局限。
报告里每个数字都必须能在 evidence 的 claims 里找到，并标明用的是哪种协议。
局限部分如实写被试数、个体差异、多重比较等问题。
```

**异常分支**：第四步之后，另外发一条

```
请查看一下 eval_000000000000 这个结果的详细内容
```

它会收到 `E_HANDLE_NOT_FOUND`，返回值里带一份最近可用的 handle 列表——**看它怎么用这份清单自愈**，这才是要拍的画面。

## 五、AGH 实际提供的能力（用得上但别漏的）

从 `packages/code/presets/standard.yaml` 读出，agent 手里有：

| 能力 | 本演示用在哪 |
|---|---|
| `todo` | 第一步显式规划，对应「任务规划」 |
| `read` / `ls` / `write` | 读项目、写报告 |
| **`shell`** | 第三步跑 pytest **自证**（每次都弹人工确认） |
| `grep` / `find` | 备选：展示它读自己的代码 |
| 我们的 10 个 MCP 工具 | 全流程 |

**两条约束：**
- 单轮请求上限 **80 步**（`max_steps`）。本演示约 25–30 步，空间充足。
- 模型 `agnes-3.0-flash` 上下文 **200K**，足够在一轮里持有全部迭代结果。

**几条容易踩的操作坑（录制前务必知道）：**

| 坑 | 后果 | 规避 |
|---|---|---|
| `use_csp=True` 必须喂 `clean_*` 产物；`use_csp=False` 喂 `feat_*` 特征矩阵 | 喂错报 `E_BAD_INPUT_KIND` | 不用管——这正是可演示的自愈路径 |
| 跨被试 5 折 CSP 可能协方差非正定 | `E_BAD_ARGUMENT`，不可恢复 | 让模型**如实记录并跳过**，这是「异常处理」展示项 |
| 单次置换次数太多 | 超时 / `OVERLOADED` | 提示词已要求分批再合并 |
| 首次 `eeg_fetch` 未缓存 | 等 11 分钟/被试 | **录前必须预下载** |
| **预先指定预处理参数** | 把「反馈调整」得分点变成了「照参数执行」 | **提示词里不要写窗口、阈值、频带**——让它自己从诊断结论推出来 |

> 你心里预期的结果区间是：被试内 CSP ≈ 0.60–0.63，跨被试 ≈ 随机。
> **但口播必须以屏幕上的实际数值为准，不许念预期值。**

## 六、实测时长与剪辑（**重要**）

**完整跑一遍实测 11.6 分钟**（含异常分支），而视频要求 3–5 分钟。所以必须剪辑。

| 阶段 | 实测 |
|---|---|
| 取数 → 诊断 → 预处理 → 特征 → 三次评估 | 约 2 分钟 |
| 三次置换 + 合并 + 留出验证 | 约 2.5 分钟 |
| 消融 + pytest 自查 + grep | 约 1 分钟 |
| evidence + 写报告 | 约 1 分钟 |
| 异常分支（另一轮对话） | 约 5 分钟 |

**剪辑原则（这条界线要拿准）：**

- ✅ **可以剪掉等待和重复**——agent 思考时的空白、加载过程、重复的进度更新
- ✅ **可以跳过中间步骤**，用字幕交代，例如「（此处省略 2 轮参数调整）」
- ✅ 用**字幕补足上下文**，比配音硬撑更清楚
- ❌ **不能拼接出没真正发生的流程**——那是伪造运行记录
- ❌ **不能篡改任何数字或界面内容**

**换句话说：剪掉等待是编辑，编造流程是造假。**

**建议的剪辑配比**（目标 4 分 30 秒）：

| 内容 | 建议时长 |
|---|---|
| 开场 + 任务输入 | 40 秒 |
| `todo` 规划 | 15 秒 |
| 诊断 + 迭代（保留 2–3 轮，其余快进或略过） | 90 秒 |
| 验证（两协议 + 置换检验） | 50 秒 |
| pytest 自查 | 30 秒 |
| 异常处置 | 40 秒 |
| 证据 + 报告 | 35 秒 |
| 收尾 | 20 秒 |

**异常分支那一轮较长**（约 5 分钟），因为它前面还带着上下文。剪辑时只保留「发提示词 → 拿到错误 → 读 suggestions → 换 handle 继续」这四个镜头就够。

## 七、录制要点

- OBS 录屏 1080p，保留鼠标轨迹；**字体放大**，否则评委看不清工具返回值
- **数据必须提前缓存好**（见「录制前的准备」），视频里不要等下载
- 出现错误分支时**不要剪掉**，那是评分项
- 不要露 API Key、不要露邮箱
- **一镜到底**：Agent 的推理过程应当是实时的。若中途卡死，如实重录，
  不要用剪辑掩盖，更不要事后补录一段「看起来跑通了」的片段
- 配音建议用**剪映**（免费、中文音色自然、自动打轴），按段生成再对齐

## 七、关于稳定性

模型当天的表现无法预先保证。因此：

- 保留一条**确定性基线路径**（`eeg_ablation` 里的基线），它一定能出结果，
  但**绝不能把它当作 agent 的输出呈现**。
- 万一模型当场卡住或绕圈，这本身是可以说明的，前提是你有 fallback 并且讲清楚。
  但不要用剪辑把一次失败的运行伪装成成功。
- **如果某条线不顺，砍掉它保证整体流畅。** 六要素里「异常处理」和「结果验证」
  是硬要求；`todo` 规划那条属于加分项，可以舍弃。
