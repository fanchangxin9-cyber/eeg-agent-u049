> **这是备案，不是主方向。** 若 EEG 主方向在 **10/10 检查点**仍跑不顺，再切到这里。
>

## 它做什么

给一个主题（比如「秋天的南通」「给 21 岁的自己」），Agent 自动：

1. **构思** — Agnes 2.5 文本模型列 3 个意象方向，等用户选
2. **写诗** — 生成一首 12 行以内的现代诗
3. **配图** — 把核心意象翻译成画面 prompt，调 Agnes Image 出图
4. **校验** — **由代码**检查硬性约束（见下）
5. **排版** — 输出竖版 HTML 长图（诗 + 插图 + 署名）

## 关键加固：把"自检"从模型判断改成代码判定

这是本备案能否通过评审的分水岭。

### 由代码判定的部分（确定性，可复现）

`lit_verify` 工具用规则而非模型来判定：

| 检查项 | 判定方式 |
|---|---|
| 行数 ≤ 12 | 按换行符计数 |
| 每行 ≤ 12 字 | 按字符计数（排除标点） |
| 禁用词 | 正则匹配「AI生成」「作为一个语言模型」「啊」「哦」等 |
| 意象具体性 | 检测是否命中空洞词表（「美丽的」「美好的」等抽象修饰） |
| 输出文件存在且可打开 | 文件系统校验 |
| 图片真实生成 | 校验返回的是有效图片文件，而非占位符 |

这些都能写进 `tests/`，构成「正常 / 边界 / 失败」三类样例。

### 无法自动判定、必须留人工入口的部分

「诗与图意象是否一致」是主观判断，**不要**让模型自称已经通过。
正确做法是：

- 工具返回**结构化待办**：列出诗中的核心意象与图中检测到的元素（可用图像模型描述）
- 输出**人工复核入口**（一个标注界面或一张对照表）
- 报告里如实写明：此项由人工复核，复核人：____

**不要在提交材料里声称这一项是自动验证的。**

## 工具清单

| 工具 | 作用 | 类型 |
|---|---|---|
| `lit_plan_topic(topic)` | 给 3 个意象方向 | 模型生成 |
| `lit_write_poem(direction)` | 写诗 | 模型生成 |
| `lit_make_image(prompt)` | 调 Agnes Image 出图 | **外部能力调用** |
| `lit_verify(poem, image_path)` | **代码判定**硬性约束 | 确定性 |
| `lit_render_html(poem, image_path)` | 输出排版 HTML | 确定性 |

注意 `lit_verify` 是纯代码，不调用模型——这正是它与原版的区别。

## 闭环 prompt 链

### Step 1 · 系统提示词（给 Agnes 2.5）

```
你是一个文学创作 Agent。用户给一个主题，你按以下步骤工作：

1. 先给 3 个不同的意象切入方向（不要直接开写），等用户选一个。
2. 用户选定后，写一首 12 行以内的现代诗，每行不超过 12 字。
3. 从诗里挑 2 个最有画面感的名词，写一段 50 字以内的画面 prompt，
   交给图像生成工具。
4. 拿到图之后调用 lit_verify 做规则校验。如果有未通过项，修改后重新校验，
   最多 3 轮。
5. 校验全部通过后再输出排版 HTML。

约束：
- 不要写"AI生成"、"作为一个语言模型"这类话
- 意象要具体（不要"美丽的秋天"，要"法桐叶压在自行车铃上"）
- 不要用"啊"、"哦"这类感叹词堆砌
- 报告里不许声称 lit_verify 之外的检查已经通过
```

### Step 2 · 图像 prompt 模板

```
A {style} illustration, {意象1} and {意象2},
muted warm color palette, soft film grain,
vertical poster composition, negative space at top for text,
no text, no watermark, no people faces
```

`{style}` 轮换：Japanese woodblock print / Studio Ghibli watercolor /
90s novel book cover / ukiyo-e / muted risograph。
