# requirements-lock.txt — 精确版本快照（pip freeze 产出）
#
# 为什么需要它：requirements.txt 全是下限写法（mne>=1.6、numpy>=1.26 …），
# 而 code_version() 只哈希 tools/eeg_pipeline.py / eeg_dataset.py / eeg_cache.py
# 三个源文件，**不含任何库版本**。后果很具体：按 requirements.txt 重装时若拿到
# 更新的 sklearn / scipy / mne，handle 依然「有效」（哈希不变），但算出来的数字
# 可能已经漂移，而且不会触发 E_HANDLE_STALE 报警。
#
# 本文件把这层缺口补上：它记录权威运行所用的**精确版本**。想逐位复现文档里的
# 数字，请用本文件而非 requirements.txt 安装：
#
#   .venv/Scripts/python.exe -m pip install -r requirements-lock.txt
#
# 权威运行环境（与 docs/ 中数字对应）：
#   生成日期  2026-10-04
#   生成方式  .venv/Scripts/python.exe -m pip freeze
#             **手工剔除了 pandas**（见下），其余逐行与 freeze 一致
#   代码版本  20b202c7ffe4（三源文件 SHA-256 前 12 位，见 tools/eeg_cache.py）
#
# 关于被剔除的 pandas==3.0.6：
#   本项目代码从不直接 import 它；实测把它**完全屏蔽**（import 抛 ImportError）后，
#   sklearn 的 LDA + cross_val_predict、mne、真实 EDF 加载（45×64×673）、
#   以及全部 108 项测试**均正常**。sklearn 在它存在时会顺手用一下，但并未把它
#   声明为依赖（`importlib.metadata.requires('scikit-learn')` 里没有 pandas），
#   mne 也只在 `[full]` 这类 extra 里才要求它。
#   → 它对本项目是**纯冗余**：只会增加安装体积与供应链暴露面。
#   若日后确有代码需要它，请连同本注释一起恢复。
#
# 注：本文件包含开发依赖（pytest / ruff），因此比 requirements.txt 更宽；
# 参赛提交只需运行期依赖时可用 requirements.txt，复现数字请用本文件。
